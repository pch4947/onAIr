# 데모 시나리오 (#246)

발표 데모 15분의 진행 순서, 엔진 패널로 보여 줄 품질 기준, 준비물과 실패 대처를 정리한다.

데모의 핵심은 **엔진 패널**이다. 패널에 나오는 항목은 우리가 서비스 품질을 평가한 기준이고, 이 기준으로 대본·선별·편성을 다듬어 왔다는 것을 보여 준다. 기준의 정의는 [CORNER_DESIGN.md](CORNER_DESIGN.md) 9.5절, 지표 계산은 엔진 `onair-report`([apps/engine/README.md](../apps/engine/README.md))를 따른다.

---

## 1. 전체 흐름 (12분 + 여유 3분)

| 시간 | 구간 | 보여 줄 것 |
| --- | --- | --- |
| 0:00–2:00 | ① 방 생성 | 선택지만 고르면 AI가 DJ 페르소나 초안을 만든다 |
| 2:00–4:00 | ② 방송 시작 | 대본·음성 생성과 송출, 채팅·신청곡·사연·게시판 입력 |
| 4:00–10:00 | ③ 코너·스테이션 차이 | 같은 입력이 코너·형식 정책에 따라 다르게 처리된다 (엔진 패널) |
| 10:00–12:00 | ④ DJ 페르소나 차이 | 같은 채팅이 DJ 성격에 따라 다른 방송이 된다 |
| 12:00–15:00 | 여유 | 질의응답, 필요하면 마이페이지 다시듣기 |

## 2. 진행 순서

### 0:00–2:00 · ① 방 생성

1. 메인 **방송 시작하기** → 형식 **토크**
2. 본 코너 **주제 토크 + 문자 소개 + 게시판 사연**, 참여 강도 **보통**
3. 페르소나 폼: **존댓말 · 차분하게 · 드물게**, 목소리, DJ 이름
4. **초안 3개 생성** (5~15초)
   - 기다리는 동안: "선택지만 고르면 DJ의 컨셉, 말투, 예시 멘트를 AI가 초안으로 만들어 줍니다."
5. 초안 하나를 고르고 예시 멘트 한 줄을 고친 뒤 **방 만들기**
   - "호스트가 마지막에 직접 다듬을 수 있습니다."

### 2:00–4:00 · ② 방송 시작

1. "방송을 준비하고 있어요" (20~30초)
   - 기다리는 동안: "엔진이 대본과 음성을 만들고, 백엔드가 이어 붙여 송출합니다."
2. **방송 듣기** → 오프닝 재생, 채팅창 위 **"지금 · 오프닝"** 안내
3. 휴대폰으로 채팅 1줄 → 화면에 바로 뜨는 것 확인
4. 신청곡 보내는 법 (채팅창 신청곡 버튼)
5. 사연 보내는 법 (채팅창 사연 보내기 버튼 — 문자 소개 코너에서 읽힘)
6. 게시판에 사연 쓰는 법 (게시판 → 글쓰기 — 게시판 사연 코너 후보)

### 4:00–10:00 · ③ 코너 · 스테이션 차이

메뉴 **테스트**로 이동한다. 진행 중인 내 방송이 그대로 열리고, 플레이어 아래에 코너·페르소나·스테이션 버튼과 엔진 로그가 있다.

| 시간 | 버튼 | 방송에서 들리는 것 | 엔진 패널에 보일 것 (실제 문구) |
| --- | --- | --- | --- |
| 4:00 | 코너 → **주제 토크** | 안내가 "채팅이 소개되고, 이야기 주제가 될 수도 있어요"로 바뀜. 보낸 채팅이 인용되거나 화제가 됨 | `코너 진입 · 주제 토크` → `입력 라우팅 · 채팅 → 채팅 후보` → `채팅 선별 · 후보 3건 중 "…" 선택 (주제 관련)` → `생성 · … · LLM 1.2초 · 인용 확인 · 안전 검사 통과 · TTS 0.8초` (화제가 바뀌면 `화제 전환 · A → B`) |
| 5:00 | 코너 → **문자 소개** | 미리 보낸 사연 2건을 닉네임과 함께 낭독 | `입력 라우팅 · 문자 → 문자 받은편지함` → `문자 코너 예고 · 받은편지함 2건` → `코너 진입 · 문자 소개` → `생성 · …` |
| 6:00 | 코너 → **곡 소개** | 신청곡을 사연과 함께 소개하고 곡 재생 | `신청곡 도착 · 곡 제목 - 아티스트` → `코너 진입 · 곡 소개` → `생성 · …` |
| 7:00 | 스테이션 → **뉴스** | 기사 브리핑. "이 방송은 청취자 의견을 반영하지 않아요" 안내. 채팅을 보내도 방송에 나오지 않음 | `기사 수집 · IT 4건, 경제 3건` → `코너 진입 · 헤드라인` → 채팅을 보내면 `입력 라우팅 · 채팅 → 방송 미반영` |
| 8:00 | 스테이션 → **음악** | 곡과 아티스트 이야기 위주. 사연 보내기 버튼이 사라짐 | `코너 진입 · 아티스트 이야기` → `다음 곡 · …`, 멘트는 곡 사이에 짧게 |
| 9:00 | (설명) | 2층 품질 지표 카드 설명 (4절) | 반영률, 제때 반영, 생성 지연, 무음·대체 멘트 |

- 코너 버튼을 누르면 이미 만든 소리(약 15초)가 나간 뒤 새 코너 첫 멘트가 나온다. 각 구간이 시작하자마자 누른다.
- 채팅이 방송에서 들리기까지 실측 약 33~35초 걸린다 (#241 머지 기준, 시나리오 측정). 4:00 구간 채팅은 3:50쯤 미리 보낸다.
- 5:00의 사연 2건, 6:00의 신청곡은 데모 전에 보내 둔다 (6절).

### 10:00–12:00 · ④ DJ 페르소나 차이

1. 스테이션 → **토크**, 코너 → **주제 토크**로 되돌린다.
2. 페르소나 → **고요** (존댓말·차분·농담 없음). 같은 채팅 "오늘 너무 피곤해요"를 보낸다 → 45~60초 듣기
3. 페르소나 → **번개** (반말·하이텐션·농담 많음). 같은 채팅을 다시 보낸다 → 45~60초 듣기
   - "같은 코너, 같은 채팅이어도 DJ 성격에 따라 완전히 다른 방송이 됩니다."
   - 패널: 두 번 모두 `채팅 선별 · … "오늘 너무 피곤해요" 선택`이 찍히고, 이어지는 `송출 · …` 대본이 달라진다.

## 3. 엔진 패널 1층 — 판단 흐름

엔진이 **무엇을, 왜** 판단했는지 실시간으로 보여 준다. 엔진 이벤트 로그(`GET /v1/stations/{id}/events`, #208)를 그대로 쓴다.

| 이벤트 | 패널 문구 예 | 보여 주는 품질 기준 |
| --- | --- | --- |
| 입력 라우팅 | `입력 라우팅 · 채팅 → 채팅 후보` / `문자 → 문자 받은편지함` / `채팅 → 방송 미반영` | 입력이 코너·형식 정책대로 배정되는가 (CORNER_DESIGN 4장 계약) |
| 채팅 선별 | `채팅 선별 · 후보 3건 중 "…" 선택 (주제 관련)` | 선별 기준(최신순·주제 관련·다양성)이 실제로 작동하는가 — RQ-A의 조작 변수 |
| 생성 | `생성 · 주제 토크 · LLM 1.2초 · 인용 확인 · 안전 검사 통과 · TTS 0.8초` | 단계별 생성 지연, 인용 누락, 안전 검사, 장애 시 `대체 멘트로 전환` |
| 코너 | `코너 진입 · …` / `코너 건너뜀 · … (소재 없음)` / `코너 대체 · …` | 편성이 끊기지 않는가 (Q-03 코너 전환) |
| 화제 전환 | `화제 전환 · A → B` | 반영 ③단계 — 채팅이 방송 흐름을 바꿈 |
| 다시 꺼내기 | `다시 꺼내기 · "…"` | 반영 ④단계 — 앞선 입력을 다시 언급 |
| 집계 언급·예고 | `집계 언급 · "피곤" 4명 / 전체 9명`, `문자 코너 예고 · 받은편지함 2건` | 개별로 읽지 못한 입력을 방송 차원에서 인정 (RQ-A 보조 조건) |
| 소재 | `신청곡 도착 · …`, `기사 수집 · …`, `사연 판정 · 관련 있음 (llm)`, `이야기 갈래 3개 준비` | 형식별 소재를 제대로 모으고 거르는가 |
| 송출 | `송출 · …` | 실제로 나간 대본 (페르소나 차이 비교) |

## 4. 엔진 패널 2층 — 품질 지표

방송 하나가 **얼마나 잘** 되고 있는지 요약한다. 기준과 계산은 CORNER_DESIGN 9.5절과 `onair-report`다.

| 질문 | 지표 | 계산 |
| --- | --- | --- |
| 제때 읽었나 | 시의성 달성률, 반영까지 걸린 시간 중앙값·P95 | 인용된 반응형 중 `quote_age_net ≤ 120초` 비율, 입력 도착 → 반영 세그먼트 재생 시작 |
| 소통이 있었나 | 반응형·독립형·문자 반영률 | 종류별 도착 중 반영된 비율 |
| 맥락에 맞았나 | `topic_match` 비율 | 인용 재생 시점에 앵커가 현재·직전이었던 비율 (필터 동작 확인용) |
| 끊기지 않았나 | 무음 시간, 대체 멘트 수, 생성 지연 P95 | 송출 공백, 대체 멘트 횟수, LLM→안전 검사→TTS 합계 |
| 같은 말을 반복하지 않나 | 같은 첫머리 비율, 직전 멘트 유사도 | 앞 5글자가 같은 멘트 비율, 직전 8개와의 3-gram 유사도 |

목표치는 아직 정하지 않았다 (9.5절). 데모에서는 값보다 **무엇을 재는지**와 이 값으로 무엇을 고쳤는지를 말한다. 예: 채팅이 들릴 때까지 279~761초 → 33~35초 (#239·#241, 곡 소개 생성 시점 조정).

사람이 판단하는 지표(의미 적합성, 분류 정확도, 소통감)는 패널에 넣지 않는다. 대본 검토 페이지(`onair-review`)와 곡간 설문으로 본다.

## 6. 준비물

- **계정**: 데모 모드 어드민 PIN(발표자), 닉네임 참가(휴대폰 청취자). PIN은 저장소에 두지 않는다.
- **휴대폰 청취자 1~2명**: 같은 방송에 들어와 채팅을 보낸다.
- **미리 보낼 입력** (② 이후, ③ 전)
  - 사연 보내기 2건 (닉네임 공개 1건, 익명 1건)
  - 신청곡 1곡 + 한마디 (10분 이하 곡)
  - 게시판 사연 1건 (방송 주제와 관련 있게)
- **채팅 문구**: "오늘 너무 피곤해요" 등 미리 정해 둔다.
- **리허설**: 같은 순서로 1회 돌려 구간별 시간을 맞춘다.

## 7. 실패 시 대처

| 상황 | 대처 |
| --- | --- |
| 초안 생성이 늦거나 실패 | "다시 생성". 그래도 안 되면 미리 만든 방송으로 넘어간다 |
| 방송이 "준비 중"에서 오래 멈춤 | 1분 넘으면 미리 띄운 예비 방송으로 이동한다 |
| 채팅이 방송에 안 나옴 | 패널에서 그 채팅의 라우팅·선별 줄을 보여 주며 "후보에 있었지만 이번엔 다른 채팅이 골라졌다"로 설명한다 (선별 기준 시연으로 전환) |
| 신청곡 음원 준비 실패 | 다른 곡으로 다시 신청하거나 6:00 구간을 패널 설명으로 대신한다 |
| 코너 버튼 뒤 전환이 늦음 | 15초 + 생성 시간이 정상임을 말하고 다음 구간 설명을 먼저 한다 |
